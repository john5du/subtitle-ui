# Subtitle UI 界面风格设计指南

> 版本：1.1 · 日期：2026-09-09  
> 设计方向：专业工作台为基础，媒体库加入适度影院感。  
> 状态：已按本文落地基础令牌、共享组件和应用界面；现行控件尺寸与弹窗结构仍以 [frontend-ui.md](frontend-ui.md) / [frontend-dialogs.md](frontend-dialogs.md) 为准。

## 1. 文档定位与使用方式

本指南定义 Subtitle UI 下一版界面的视觉语言，以及这些规则在电影库、剧集工作区、字幕操作、设置和反馈中的应用。目标是让后续开发者能根据同一套规则完成页面，而不必逐页重新选择颜色、字号和尺寸。

视觉令牌、共享控件和主要工作区已按本文实现。组件接口、路由和业务行为保持不变；尺寸体系仍沿用现行 UI / 弹窗规范。

## 2. 产品定位与设计目标

Subtitle UI 是面向个人媒体库的字幕管理工具。典型任务包括找到影片、查看字幕、上传或下载字幕、校正时间、统一语言标签，以及为整季剧集匹配字幕文件。

用户需要同时看到媒体身份和操作对象。影片标题与海报帮助定位；字幕文件名、语言、格式、来源和集数帮助判断实际操作。因此，全局界面采用专业工作台的秩序，影院感集中体现在媒体图像和浏览节奏上。

### 2.1 五项设计原则

1. **对象明确。** 每次操作前都能确认影片、季、集及字幕文件；不通过过度截断或隐藏上下文换取整齐。
2. **状态清楚。** 选中、悬停、键盘焦点、加载、缺失和失败各有独立表达。
3. **密度可持续。** 列表紧凑但可读，批量处理保留足够比较空间；触屏通过重排和扩大操作区域保证可用性。
4. **色彩有职责。** 蓝紫用于操作与选择，绿/琥珀/红用于业务状态，海报提供主要视觉变化。
5. **全流程一致。** 同一字幕在电影抽屉、剧集面板和批量映射中，名称、语言、状态和操作层级保持一致。

### 2.2 预期观感

关键词：安静、精确、清晰、适度柔和、有媒体质感。

整体以不透明中性色表面、少量细分隔、6–12px 圆角和自然中文排版建立风格。强调色只出现在主要按钮、选中位置、链接和焦点等有意义的位置。

不采用全屏氛围渐变、大面积玻璃模糊、霓虹发光、拟物凹凸或每张卡片都悬浮的处理。这些效果不符合长时间阅读文件名和密集比较字幕的目标。

## 3. 当前基础与改造边界

以下观察来自当前源码和现行文档，不代表已完成浏览器视觉审查。

| 当前基础 | 目标设计 |
| --- | --- |
| 全局主操作以黑白为主 | 使用稳定的蓝紫操作色，与中性工具栏区分 |
| `--radius` 为 4px，Tailwind 的 md/sm 再减 2/4px | 建立 4/6/8/12px 层级，解决部分控件近乎直角的问题 |
| 按钮、徽标和部分标题使用等宽字体、英文大写及较大字距 | 界面文字使用无衬线；时间码、路径和技术值保留等宽 |
| 已有 Light、Dark、OLED、System 主题 | 完整保留，分别定义表面与前景组合；System 仍跟随系统 |
| 电影与电视剧共享列表外壳、海报卡片及网格计算 | 保留共享结构，统一升级工具栏、行状态和海报信息层级 |
| 电影用 md 抽屉，电视剧用 xl 抽屉 | 沿用对象详情抽屉模式和统一宽度 |
| 设置集中在 dashboard，含扫描状态和集成配置 | 保留信息架构，通过分组与文字层级提高可读性 |
| 已有操作锁定、上传遮罩、帮助提示和反馈组件 | 保留业务语义，统一视觉表达，减少无意义脉冲效果 |

第一阶段不包含新增首页统计大屏、命令面板、快捷键系统、字幕编辑器、推荐内容、全局搜索、AI 功能入口或播放记录。此类能力需要单独的产品设计。

前一轮风格示意用于比较视觉方向；其中常驻的右侧详情栏、示例数据和演示按钮，不构成对现有抽屉架构或真实业务功能的变更要求。

## 4. 页面结构与布局

### 4.1 全局外壳

桌面维持“左侧导航 + 右侧工作区”。导航承担现有一级页面切换及全局偏好，不与页面局部工具栏争夺视觉重心。

| 项目 | 目标规则 |
| --- | --- |
| 展开导航宽度 | 沿用 12.75rem，默认根字号下约 204px |
| 收起导航宽度 | 沿用 4.5rem，约 72px |
| 主要工作区 | 弹性占满剩余宽度，不按宣传页设置窄内容栏 |
| 设置内容区 | 沿用最大 64rem，宽屏居中；表单保持可扫描长度 |
| 页面外侧留白 | 桌面 24px、平板 16px、手机 12px；属于统一目标值 |
| 页面内部大区间距 | 24px；密集工作区可用 16px |
| 页头 | 标题、必要计数、页面操作；内容决定高度，常规约 56–64px |
| 工具栏 | 36px 控件、8px 控件间距；按空间换行 |

布局示意：

```text
┌──────────────┬───────────────────────────────────────────┐
│ Subtitle UI  │ 页面身份 / 当前上下文                     │
│              ├───────────────────────────────────────────┤
│ 现有一级导航 │ 刷新         搜索       排序 / 视图切换    │
│              ├───────────────────────────────────────────┤
│              │ 海报网格或媒体列表                        │
│              │                                           │
│ 全局偏好     ├───────────────────────────────────────────┤
│              │ 结果数量 / 分页                           │
└──────────────┴───────────────────────────────────────────┘
```

当前列表没有独立大标题区域时，不为了套用示意增加一个空白页头。导航选中项已足够说明页面身份的，可以保留紧凑布局。

### 4.2 表面层级

| 层级 | 典型对象 | 表现 |
| --- | --- | --- |
| 画布 | 应用背景、内容外边距 | `background`，无阴影 |
| 导航 | 侧栏、移动端导航 | 建议新增 `sidebar`，与工作区有轻微色差 |
| 内容 | 列表、设置分组、字幕区域 | `card`，必要时 1px 中性边框 |
| 局部强调 | 悬停、只读摘要、分组背景 | `surface-subtle/strong/hover` |
| 浮层 | 下拉菜单、提示、抽屉、弹窗 | `popover`，不透明，边框与适量阴影 |
| 遮罩 | 模态背景、阻塞中的上传 | `overlay/overlay-strong`，说明明确 |

同一内容区最多采用两层有边框容器。列表行通常依靠水平分隔线分组，不把“整页面板 → 分组卡片 → 行卡片 → 字段卡片”层层套叠。

### 4.3 滚动与粘性区域

- 桌面列表继续在工作区滚动，工具栏和分页保持可达；分页不得盖住最后一行。
- 抽屉和 md/lg/xl 弹窗由正文区滚动，标题、关闭按钮及页脚保持稳定。
- 两栏剧集工作区可以分别滚动剧集列表与字幕详情，但每一栏内部避免再嵌套多个短滚动区。
- 手机优先单列连续内容；固定操作区必须为正文预留空间，并考虑底部安全区与软键盘。
- 关闭详情后保留媒体库的搜索、排序、分页和滚动上下文，焦点返回原入口。

## 5. 色彩系统

### 5.1 使用原则

全局采用冷中性灰与蓝紫强调色。影院感由海报、深色主题和图像留白表达，不引入第二套全局金色按钮。

使用语义令牌调用颜色，组件不得直接绑定某个主题的色值。下表是建议初始值，实际实现仍需检查透明叠加、悬停和禁用后的最终颜色。

### 5.2 基础主题令牌

| 令牌 / 角色 | Light | Dark | OLED |
| --- | --- | --- | --- |
| `background` / 画布 | `#F5F6F8` | `#14161B` | `#000000` |
| `sidebar` / 导航，建议新增 | `#EDEEF2` | `#101217` | `#000000` |
| `card` / 内容表面 | `#FFFFFF` | `#1B1E25` | `#0B0D12` |
| `popover` / 浮层 | `#FFFFFF` | `#222630` | `#171B23` |
| `foreground` / 主文字 | `#222733` | `#EDEFF5` | 同 Dark |
| `muted-foreground` / 次文字 | `#5E6675` | `#A9B0BF` | 同 Dark |
| `foreground-subtle` / 占位等辅助文字 | `#6B7280` | `#9BA4B5` | 同 Dark |
| `border` / 装饰与结构分隔 | `#DDE0E7` | `#343945` | `#343945` |
| `input` / 必须识别的控件边界 | `#7D8595` | `#727C8F` | 同 Dark |
| `surface-subtle` / 弱底色 | `#F0F1F5` | `#20242D` | `#131720` |
| `surface-strong` / 次级强调面 | `#E9EBF1` | `#272C36` | `#1B202B` |
| `surface-hover` / 中性悬停 | `#E9EAF0` | `#2C313C` | `#232A36` |
| `primary` / 主按钮填充 | `#5653CC` | `#A5A0FF` | 同 Dark |
| `primary-foreground` / 主按钮文字 | `#FFFFFF` | `#1B173D` | 同 Dark |
| `selection` / 持续选中底色，建议新增 | `#EEEDFF` | `#302D4A` | `#27233F` |
| `selection-foreground` / 选中名称，建议新增 | `#5653CC` | `#A5A0FF` | 同 Dark |
| `ring` / 键盘焦点 | `#5653CC` | `#A5A0FF` | 同 Dark |

令牌映射补充：

- `card-foreground`、`popover-foreground` 使用对应主题的主文字色。
- `secondary`、`muted` 使用 `surface-subtle`；其前景分别使用主文字与次文字。
- 现有 `accent` 继续表示中性互动底色，可映射到 `surface-hover`；`accent-foreground` 使用主文字。不要把所有使用 `accent` 的悬停位置直接改成蓝紫底。
- 现有 `foreground-muted` 可合并映射到次文字色，避免维护数套过于接近、对比度不稳定的灰字。
- 新增 `selection` 的原因是区分持久选中与临时悬停；如果选择现有令牌承接，也必须维持这两个状态的差异。
- `ring-offset` 跟随控件实际相邻表面；`ring-soft` 只能补充外圈效果，不能代替可见实色焦点环。
- `input` 比 `border` 更清晰，只用于需要轮廓才能识别的字段和控件，不能用于所有面板分隔。

### 5.3 状态颜色

下表的“文字/图标”对应现有 `*-muted` 角色，“底色”对应 `*-soft`。状态标签优先使用浅底与深字或深底与亮字，避免整块高饱和填充。

| 状态 | Light 文字/图标 | Light 底色 | Dark/OLED 文字/图标 | Dark/OLED 底色 |
| --- | --- | --- | --- | --- |
| 成功 | `#166534` | `#ECFDF3` | `#86EFAC` | `#173428` |
| 警告 / 待处理 | `#92400E` | `#FFF7E8` | `#FCD34D` | `#3C2D19` |
| 错误 / 危险 | `#B91C1C` | `#FEF2F2` | `#FCA5A5` | `#3D2228` |
| 信息 / 进行中 | `#1D4ED8` | `#EFF6FF` | `#93C5FD` | `#1F304B` |

`*-border` 如用于装饰，可由该状态文字色以约 20%–30% 混入状态底色；如边界承担识别功能，则单独检查非文字对比度。普通成功、警告和信息提示不使用实心主按钮造型。

危险确认按钮使用 Light `#B91C1C` + 白字，Dark/OLED `#FCA5A5` + `#3D2228` 文字；`destructive` 与 `destructive-foreground` 必须成对设置。

语义约定：

- “已安装”仅说明字幕文件存在或安装成功，不表示翻译质量、同步准确度或语言覆盖已经验证。
- “缺少字幕”通常是待处理状态，使用中性或琥珀色；“操作失败”才使用错误红。
- “语言未知”使用中性标签，不直接视为失败。
- “内嵌字幕”使用中性只读标识，与可修改的外挂字幕区分。
- 缺集与缺字幕分别显示；Sonarr 完整性结果不能混用为字幕完整性。
- 已启用、配置完整、连接测试成功是不同状态，不用同一个绿点代替。

### 5.4 颜色组合校核记录

下列比值按上述不透明 sRGB 色对计算，显示值保留两位小数；判定使用未四舍五入的结果。它们是设计令牌检查，不能代替实现后的页面无障碍检查。

| 色对 | Light | Dark |
| --- | --- | --- |
| 主文字 / 内容表面 | 14.94:1 | 14.51:1 |
| 次文字 / 弱底色（Dark 取更亮的 hover 底色） | 5.12:1 | 5.99:1 |
| 占位文字 / 输入表面（Light 白色，Dark 浮层色） | 4.83:1 | 6.03:1 |
| 主按钮文字 / 主按钮填充 | 5.99:1 | 7.34:1 |
| 选中文字 / 选中底色 | 5.19:1 | 5.67:1 |
| 输入边界 / 相邻表面（Light 弱底色，Dark 浮层色） | 3.29:1 | 3.60:1 |
| 成功文字 / 成功底色 | 6.76:1 | 9.60:1 |
| 警告文字 / 警告底色 | 6.66:1 | 9.21:1 |
| 错误文字 / 错误底色 | 5.91:1 | 7.59:1 |
| 信息文字 / 信息底色 | 6.16:1 | 7.36:1 |

正文和有信息意义的辅助文字以至少 4.5:1 为基线；用于识别控件或状态的非文字元素以至少 3:1 为基线。装饰分隔线不承担同一职责。依据：[W3C 文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[W3C 非文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。

### 5.5 主题与影院感的边界

- 首次主题选择继续跟随系统，不因影院风格强制 Dark。
- Dark 的层级依靠不同亮度的实色表面；OLED 保留纯黑画布，但浮层和内容区仍需要边界。
- 海报原图保留色彩，不统一做紫色、金色蒙版，也不自动从每张海报生成按钮配色。
- 只在海报文字覆盖区使用局部暗色底；工作区正文不铺设海报模糊背景。
- 海报角标建议使用白字与约 80% 黑色底，并以极亮、极暗海报检查可读性。
- 视频画面区域可以固定黑色；播放器外的页头、正文和操作仍跟随应用主题。

## 6. 字体与文字排版

### 6.1 字体职责

界面文字沿用本地 Geist Sans 及中文系统回退（PingFang SC、Microsoft YaHei 等），不新增外部字体请求。等宽字体仅用于时间码、集数编码、需要对齐的数字及独立路径/技术信息区。

当前本地 Sans 文件仅声明 400 字重，Mono 声明 300/400。下表中的 500/600 是目标视觉层级；实现时应补充可用的本地字重资源，或明确使用系统回退。不能假设现有文件已经提供这些字重，也不以极细字重表达次要信息。

| 角色 | 字号 / 行高 | 字重 | 场景 |
| --- | --- | --- | --- |
| 页面标题 | 22 / 30px | 600 | 设置页、必要的页面身份 |
| 抽屉 / 弹窗标题 | 18 / 26px | 600 | 影片、剧集、操作名称 |
| 区域标题 | 14 / 22px | 600 | 外挂字幕、集成配置、映射结果 |
| 正文 / 列表主名称 | 14 / 22px | 400–500 | 电影名称、字幕文件名、表单说明 |
| 控件文字 | 14 / 20px | 500 | 按钮、下拉选择、导航 |
| 辅助信息 | 12 / 18px | 400 | 年份、来源、大小、更新时间 |
| 技术值 | 12–13 / 20px | 400，等宽 | 时间码、路径、S01E02 |
| 字幕预览正文 | 16 / 26px | 400 | 中文与原文对白 |
| 手机可编辑字段 | 至少 16 / 24px | 400 | 搜索、偏移量、设置输入 |

除必要的非关键信息外，不使用小于 12px 的文字；当前 10px 海报角标、微型标签不作为目标默认值。

### 6.2 排版规则

- 按钮和导航使用自然语言大小写，去掉全局 `uppercase` 和宽字距；格式缩写 SRT、ASS、MCP 仍保留原有大写。
- 中文正文不增加字距。英文小标签如需区分层次，可用不超过 0.02em 的轻微字距，但不形成另一套字体风格。
- 同一区域使用最多三层文字权重：主名称、辅助信息、状态。不要同时叠加粗体、强调色、大写和边框。
- 海报标题最多两行；列表标题允许两行或按列宽省略。完整名称须能在详情中读取，不能只依赖鼠标悬停。
- 字幕文件名保持原始可识别信息；来源、文件大小和日期降为辅助层。紧凑状态允许省略，详情和确认操作必须可查看完整名称。
- 长路径在详情中允许断行或采用有明确边界的横向滚动区域，不撑宽整个弹窗。
- 中英双语字幕上下排列，两种语言都保持足够对比度；中文字号不通过压缩原文字号换取空间。
- 英文版本预留约 30% 文案扩展空间，优先换行而非缩小字体。

## 7. 间距、圆角、边框与阴影

### 7.1 间距尺度

使用 4px 基准，主要尺度为 4、8、12、16、20、24、32px；图标与短标签可用 6px。

| 关系 | 目标间距 |
| --- | --- |
| 图标与标签 | 6–8px |
| 同组按钮 | 8px；字幕密集行可用 6px |
| 标签与字段 | 6–8px |
| 表单字段之间 | 16px |
| 字幕卡片内部 | 12–16px |
| 相关内容区域之间 | 16px |
| 设置分组之间 | 24px |
| 弹窗桌面内边距 | 沿用 24px |
| 弹窗手机内边距 | 沿用 20px，并叠加安全区 |

### 7.2 圆角尺度

| 对象 | 目标圆角 |
| --- | --- |
| 小型标签、格式角标 | 4px |
| 按钮、输入、菜单项 | 6px |
| 内容面板、海报、选中导航项 | 8px |
| 桌面浮层 / 弹窗 | 12px |
| 手机底部弹层 | 顶角 16px，沿用现有形态 |
| 靠屏幕边缘的侧栏与抽屉 | 贴边侧不增加装饰圆角 |

实现建议：将基础 `--radius` 目标设为 8px，可与现有 Tailwind 的 lg/md/sm 映射形成 8/6/4px；为 12px 弹窗另设统一语义令牌，不再单纯放大基础变量，否则所有控件会一起变圆。

不将按钮、搜索框和标签全部做成胶囊；仅真正的分段切换控件可以采用连续的包裹结构。

### 7.3 阴影与分层

普通内容面板和海报默认无阴影。菜单及小浮层可使用约 `0 4px 16px` 的轻阴影；弹窗可使用约 `0 16px 48px` 的扩散阴影。建议 Light 阴影黑色透明度 10%–16%，Dark/OLED 为 25%–40%，最终以相邻层可区分为准。

遮罩建议 Light 使用冷深色约 40%–48%，Dark/OLED 使用黑色约 55%–65%。在既有两层操作流程中，保证上层确认弹窗清晰，避免每层重复加深到完全看不见被操作对象。

堆叠关系统一为：普通内容 < 粘性工具区 < 抽屉遮罩与抽屉 < 抽屉内菜单/帮助 < 上层操作弹窗及其浮层 < 阻塞上传层。Toast 的位置避开主要操作区；具体数值集中维护，不能通过页面内不断抬高 z-index 解决遮挡。

## 8. 基础控件规范

### 8.1 密度与触摸区域

沿用 [现行密度约定](frontend-ui.md#control-density) 的四档结构：

| 档位 | 现有尺寸 | 目标使用方式 |
| --- | --- | --- |
| 默认 | 40px | 表单输入、登录、弹窗主要操作 |
| 工具栏 | 36px | 搜索、筛选、排序、视图、导航辅助按钮 |
| 行操作 | 手机 40px / `sm+` 32px | 字幕卡片与密集列表操作 |
| 微型 | 28–32px | 分页附属控件、少量三级操作 |

按钮和输入优先通过 `size` 使用共享规格；行操作继续使用 `control-sizes.ts` 中的共享令牌。

触屏目标是有效点击区域至少 44×44px，允许按钮视觉保持紧凑，但点击区域不能互相覆盖。该目标比当前 40px 行操作更大，是后续需统一补齐的设计差异；不能只依据屏幕宽度判断触屏，因为大尺寸平板同样可能采用粗指针。

44px 是本项目的触屏舒适度目标。WCAG 2.2 AA 的目标尺寸条款为至少 24×24 CSS px，或满足相应间距等例外，二者不应混为一谈。依据：[W3C Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。

### 8.2 按钮层级

| 类型 | 视觉 | 使用场景 |
| --- | --- | --- |
| Primary | 蓝紫实底、配对前景 | 当前任务提交、确认安装、保存设置 |
| Outline | 中性边界、透明或实色底 | 取消、关闭、替换、次要操作 |
| Secondary | 中性浅底 | 同组辅助操作、低层级切换 |
| Ghost | 默认无明显边框 | 工具栏图标、表格辅助入口 |
| Destructive | 红色文字/浅底；最终确认可实底 | 删除、清理等危险操作 |
| Link | 可识别的链接样式 | 外部媒体信息、详情跳转 |

每个独立任务区域最多一个主要提交按钮；浮层打开后，视觉主操作属于最上层任务。字幕列表不能让每一行都出现蓝紫色实心按钮。

常用动作使用“图标 + 短文案”；刷新、收起、视图等熟悉动作可用纯图标，但必须有可访问名称及键盘可触发的提示。不要依靠图标形状区分容易误操作的替换与删除。

### 8.3 状态矩阵

| 状态 | 控件 / 列表表现 |
| --- | --- |
| Default | 中性表面；轮廓、名称、操作区域可辨 |
| Hover | 中性 hover 底色，不改变尺寸和布局 |
| Pressed | 同色系稍深或稍强的底色，不使用缩放跳动 |
| Selected | 持续 selection 底色，辅以文字权重、指示线或勾选语义 |
| Focus-visible | 2px 实色焦点环，必要时 2px 分隔；保留原选中或错误状态 |
| Disabled | 淡化非关键外观，禁用交互；必要时说明原因 |
| Loading | 操作位置显示小型进度图标及“保存中”等文案，宽度稳定 |
| Invalid | 字段错误边界、字段旁错误说明；保留标签和输入值 |

状态可以组合：选中项悬停仍然能看出选中；错误字段获得焦点时仍有错误说明。禁用和加载不能只靠整张卡片变透明表示。

### 8.4 输入、选择与开关

- 字段有常驻标签，placeholder 只提供示例。
- 搜索保留现有清除入口和防抖行为；清除按钮保持可见焦点与可点击尺寸。
- 排序和视图控制统一在列表工具栏，列表视图切换不能改变搜索上下文。
- 下拉面板使用 popover 实底，与触发器对齐；长选项允许换行，菜单项不能超出可用视口。
- 开关开启状态使用主色及明确的位置变化；开启不等于测试连通成功。
- 密钥字段保持遮掩，沿用“已配置”的独立提示；保存空值保留原密钥的现有语义必须用清晰文案表达。
- 主要输入字段、错误说明和提交按钮应在同一阅读路径上。

## 9. 媒体库：电影与电视剧

### 9.1 共享工具栏

沿用 `LibraryListShell`、搜索组件、排序组件、视图切换和分页，避免电影与电视剧各自生成一套工具栏。

桌面工具组维持“导航辅助/刷新”与“搜索/排序/视图”的分工。手机搜索优先独占一行，其余控件换行，不把所有操作压缩成没有标签的小图标。

刷新表示重新读取当前页面；扫描表示重新扫描媒体库。名称、图标提示与加载文案必须区分这两个动作。

### 9.2 海报网格

- 继续使用 2:3 海报比例，不裁成正方形或横向影片横幅。
- 初始改造沿用 176px 最小列宽、12px 网格间距和现有列数/分页计算，避免 CSS 网格与分页数学不一致。
- 如果后续调整列宽和间距，同步更新 `card-grid.ts`、共享样式和相应校验，不在某个列表写另一套网格。
- 海报下方显示最多两行标题和一行辅助信息。名称不覆盖在复杂图像上。
- 海报角落最多放一个聚合角标；电影字幕数量与电视剧现有聚合值须明确含义，不能随意将“集数”改标为“字幕完整率”。
- hover 仅改变卡片底色或边界，不放大海报、不移动相邻卡片；键盘焦点围绕整个可操作卡片。
- 持续选中对象与 hover 有差异；从详情返回时可找到之前打开的对象。
- 海报缺失或加载失败时显示同尺寸中性占位和媒体图标，不使用随机渐变伪装封面。
- 不在海报悬停层集中放置删除、转换等字幕操作；先进入详情确认对象。

影院感来自连续、整齐的图像比例和充足的标题空间。页面顶部不增加大型推荐横幅，也不以减少每屏有效内容为代价营造氛围。

### 9.3 列表视图

推荐信息顺序为媒体身份、现有字幕或集数摘要、必要元数据、管理入口；以真实现有字段为准，不新增没有数据支持的质量评分。

- 表头使用 12px 次文字，行主名称使用 14px；不将整行降到 caption 字号。
- 单行数据目标高度约 48px，包含两行媒体信息时约 64px；允许长文案增高。
- 主名称列优先获得空间，数字及操作列保持稳定对齐。
- 数字使用等宽数字特性；日期、字幕数量等不依靠含糊图标表达。
- 同一行只设一个明确的主要进入行为；若包含独立按钮，点击按钮不重复触发行打开。
- 分页属于列表，不漂浮到字幕详情上方；不同视图保持相同分页语义。

## 10. 电影字幕抽屉

继续使用 `DialogDrawerContent size="md"`。电影详情打开后，字幕管理是视觉核心；头部海报是定位辅助。

内容顺序：影片身份 → 已有的影片级操作 → 外挂字幕 → 只读内嵌字幕及相关状态。

| 区域 | 设计规则 |
| --- | --- |
| 头部 | 小海报约 64–80px 宽，标题、年份与必要媒体信息；为右上角关闭按钮留足空间 |
| 次要媒体信息 | 原名、外部资料链接和技术信息降一级显示，长路径进入可展开详情 |
| 影片级操作 | 上传、SubHD 搜索、规范化等按现有能力显示，区分入口与最终提交 |
| 字幕列表 | 展示真实文件名，格式、语言、来源、大小和更新时间按层级排列 |
| 内嵌字幕 | 明确标为只读，不复用外挂字幕的替换、转换或删除操作 |

字幕卡片内使用一层容器：顶部为文件名与格式；中部为辅助信息；底部为行操作。12–16px 内边距，卡片间距 8–12px。

桌面保留当前常用操作的可达性，统一降低行内按钮视觉权重。手机沿用现有更多菜单收纳转换、偏移、删除等操作；菜单中的危险项需有文字与分隔，不能只在桌面用红色强调、到手机又丢失危险语义。

“预览”仅在需要区分上下文时细化为“预览字幕”与“播放预览”。播放入口继续遵循 Jellyfin 的现有可用性条件，不为视觉完整性显示无效播放器。

## 11. 电视剧与整季工作区

### 11.1 单集字幕管理

沿用 xl 抽屉以及现有单集管理/批量工作模式。页头包含剧名、季选择和当前模式；这些上下文在切换集数后保持可见。

宽布局中，集列表与字幕详情并列；集列表建议宽度 240–280px，其余空间交给字幕详情。两栏布局仅在容器宽度足够时启用，建议至少约 900px；不能只按浏览器宽度判断，因为抽屉宽度受自身令牌约束。

窄容器优先单列重排，维持当前季、当前集与返回集列表入口的可达性；具体选择沿用现有组件行为，不在视觉改造中擅自增加路由。

集列表一行包括 S01E02、标题与状态摘要。集数编码使用等宽，标题可以换行；当前集使用 selection 样式，缺字幕使用文字标签。字幕数不等于是否拥有中文字幕。

### 11.2 整季批量字幕

以“来源 → 映射核对 → 提交结果”的工作顺序组织现有批量能力，不要求新增步骤路由。

| 区域 | 需要看清的内容 |
| --- | --- |
| 来源 | 本地文件/压缩包或 SubHD 季包，以及真实选中来源 |
| 映射行 | 目标集数、源文件名、当前匹配或冲突状态、已有映射调整控件 |
| 提交区 | 当前选择范围、实际可提交数量、存在的问题、提交动作 |
| 结果 | 已成功、失败、未处理项分别显示，并保留失败原因 |

映射表目标行高至少 48px；长文件名允许两行或展开。用于比较源和目标的关键列不能缩成两个都省略到只剩开头的字段。

匹配状态使用“已匹配”“未匹配”“冲突”等明确文字。只有在数据确实提供时才展示具体状态；不生成“高置信度”等主观标签。

替换已有字幕的对象与范围须在提交前可见。危险确认保留现有流程，备份说明遵循帮助提示约定；不能把主确认句藏到问号或感叹号后面。

批量处理中使用真实进度；若没有总量就显示不定进度。部分失败时，不用一个绿色 Toast 代表全批完成，也不通过再次全量提交掩盖失败项。

### 11.3 Sonarr 完整性

完整性信息只出现在相关季/集上下文，区分本地存在、缺集与搜索请求状态。队列提交成功应表述为“已提交搜索”，不表述为“已下载”。集成关闭、配置不足和请求失败采用不同提示，避免全部显示为“没有缺集”。

## 12. 弹窗、帮助与高密度操作

### 12.1 沿用尺寸体系

以下是现行尺寸的设计摘要，精确视口限幅与响应式行为仍以 [frontend-dialogs.md](frontend-dialogs.md) 和共享组件为准。

| 类型 | 桌面最大宽度 / 高度规则 | 用途 |
| --- | --- | --- |
| 模态 sm | 32rem；内容自适应，上限 90vh | 删除/替换确认、上传标签、偏移、格式转换 |
| 模态 md | 42rem；高度 min(40rem, 90vh) | SubHD 搜索、压缩包条目选择 |
| 模态 lg | 56rem；高度 min(52rem, 90vh) | 规范化、整季批量、字幕文本、日志 |
| 模态 xl | 72rem；高度 min(56rem, 90vh) | 视频与字幕预览 |
| 抽屉 md | 常规 680px，xl 760px，受视口限幅 | 电影字幕管理 |
| 抽屉 lg | 常规 840px，xl 1040px，受视口限幅 | 通用密集详情 |
| 抽屉 xl | 常规 840px，xl 1240px，受视口限幅 | 电视剧工作区 |

模态在小于 sm 时沿用底部弹层，最大 92dvh；侧抽屉在手机沿用全屏形态。正文实际可用高度必须考虑浏览器与软键盘。

### 12.2 通用结构

- 头部：标题及必要帮助入口，不堆放功能说明段落。
- 正文：md/lg/xl 使用 `DialogBody`；错误与操作关键说明直接可见。
- 页脚：分隔线、取消/关闭与主操作，沿用共享布局；桌面右对齐，手机保持现有堆叠次序。
- 关闭：继续使用抽屉/弹窗内置入口，不额外再放一个关闭图标。
- 焦点：打开后进入合理位置；关闭返回触发器；嵌套操作结束后返回所属抽屉。

解释性内容使用 `DialogTitleWithHelp` / `DialogHelpTip`。危险确认对象、错误、输入规则和影响范围直接留在正文；帮助泡泡只承担次要解释。

### 12.3 各操作的呈现重点

| 操作 | 重点 |
| --- | --- |
| 上传 / 替换 | 明确目标影片及文件；显示真实上传状态；延续现有备份提示 |
| 时间偏移 | 数值与单位邻近；正负方向与现有实现保持一致，提供与实际含义一致的例子 |
| 语言规范化 | 原名称和目标名称对照、实际冲突、应用范围；不能只显示一个“优化”按钮 |
| 格式转换 | 源格式、目标格式、现有选项；不要伪装成任意格式都可转换 |
| 压缩包条目选择 | 完整条目身份、支持状态和确认选项；选中行与悬停行区分 |
| SubHD 搜索 | 来源、结果标题、语言等已有信息、下载状态；限流/验证码提示留在结果区 |
| 删除 / 批量删除 | 操作对象、数量、不可忽略的影响和原有备份说明 |

## 13. 字幕与视频预览

### 13.1 字幕文本

字幕预览继续使用 lg 弹窗。头部保持影片/字幕对象身份，正文提供清晰可读的对白。

- 字幕序号与时间码是辅助信息，12–13px 等宽字体；对白使用 16px 无衬线。
- 双语上下排列，同一条 cue 内保持 4–6px 间距，不把原文压成低对比度脚注。
- cue 之间依靠 12–16px 间距或细分隔线区分，不给每句对白增加厚卡片边框。
- 原始 ASS 或其他内容如果当前以源码展示，保留格式和换行；不在样式改造中暗示已经支持新的解析视图。
- 预览是只读内容，不显示暗示可编辑的光标、工具栏或“保存”按钮。

### 13.2 播放预览

沿用 xl 弹窗和现有 ArtPlayer。视频区域用黑色承载，按真实画面比例等比显示；常见 16:9 可作初始占位，不强行裁切其他比例内容。

连接、缓冲与错误在视频区域内明确显示，关闭入口始终可达。字幕选择等已有控制与播放器操作分层，不能重复绘制一套播放按钮。Jellyfin 的连接信息、访问密钥及内部代理细节不进入用户播放界面。

## 14. 设置、登录与日志

### 14.1 设置

沿用 dashboard 的扫描摘要与现有设置分组：外观、SubHD、Sonarr、Jellyfin、MCP、字幕转换和系统信息。各分组使用普通无衬线标题，去掉大字距和装饰性等宽标题。

设置行维持至少 56px 高度；辅助说明导致增高时自然扩展。桌面标签在左、控件在右，手机变为上下排列，字段占可用宽度。

每个集成面板有独立的当前状态、字段、测试/保存反馈。测试连接是次操作，保存是主操作。错误紧靠相关字段或该面板，不通过全页状态色让用户猜测哪个服务失败。

扫描摘要继续用紧凑状态条，不扩展成多个大号统计卡片。保留扫描状态、数量和警告的真实含义；不为了视觉丰富增加无法支持决策的图表。

### 14.2 登录

单列登录面板建议最大 400–420px，页面中水平居中，在短屏或软键盘打开时允许滚动。保留产品标识、简短说明、令牌标签、输入、提交和就地错误。

应用首次使用的字体、背景与按钮风格和登录后完全一致。密钥内容不可被装饰性展示、日志说明或示例值暴露；错误后保留用户可修正的上下文。

### 14.3 操作日志

继续使用 lg 弹窗。时间、动作、对象和结果形成稳定阅读顺序；操作类型与文件名保持完整含义，失败原因可进入已有详情或展开区域。

时间列使用等宽数字，结果使用文字状态。清空日志作为低频危险操作，与刷新、分页分开。回滚、备份等仅在当前界面已有相应能力时按实际状态展示，不将后端存在的接口自动扩展为新 UI 入口。

## 15. 空状态、加载与反馈

| 场景 | 表达方式 | 可用动作 |
| --- | --- | --- |
| 首次媒体列表加载 | 与网格/列表结构一致的静态骨架，保留工具栏框架 | 按当前可用性决定 |
| 已有数据刷新 | 保留已有内容，刷新按钮显示加载，不清空整个页面 | 延续实际操作锁定范围 |
| 媒体库为空 | 复用 `EmptyPanel`，说明没有可用媒体 | 提供现有扫描或设置入口 |
| 搜索无结果 | 显示与当前搜索有关的空结果说明 | 清除搜索 |
| 字幕为空 | 明确当前影片/单集尚无外挂字幕 | 已支持的上传、搜索入口 |
| 网络或服务失败 | 局部错误、短原因与恢复途径 | 重试或检查对应设置 |
| 提交进行中 | 原位置进度图标与动词，不定进度或真实计数 | 禁止重复提交 |
| 部分成功 | 汇总成功/失败/未处理数量，保留逐项结果 | 仅提供现有可行恢复动作 |

空状态图标约 24–32px，文案通常一至两行；不使用巨大插画撑高工作区。

Toast 用于短暂结果反馈，不是唯一的错误载体。表单错误保留在字段附近，批量错误保留在结果区域，长流程状态保留在任务所在页面。成功文案应区分“已提交”“已保存”“已安装”和“已完成扫描”。

上传阻塞层沿用现有操作锁语义，展示真实状态与必要说明。没有取消能力时不画“取消上传”；不要为了样式统一扩大锁定范围或解锁本应保护的操作。

## 16. 动效与图标

### 16.1 动效目标

| 类型 | 目标时长 | 规则 |
| --- | --- | --- |
| hover / focus / 颜色变化 | 100–140ms | 不改变布局 |
| 菜单 / 帮助浮层 | 120–160ms | 简短显隐，不弹跳 |
| 弹窗显隐 | 160–200ms | 小幅过渡，内容尽快可读 |
| 抽屉进入 / 退出 | 200–240ms | 沿既有方向移动，不夸张回弹 |
| 成功状态强调 | 一次性、短于 500ms | 不持续闪烁 |

这些是目标值；当前全局 90/220/360ms 等令牌应在未来统一调整，不在每个组件单独设置时长。保留现有缓动族，避免引入多套类似曲线。

有意义的加载图标可以持续旋转；整页和整张字幕卡片不应持续呼吸。海报不做默认入场队列动画，分页和筛选不依靠大面积位移动效表达。

尊重 `prefers-reduced-motion`：去掉位移、缩放和非必要循环，通过静态状态图标及文案说明进度。

### 16.2 图标

沿用 Lucide，不混用填充图标、Emoji、不同线宽的图标库。工具栏与行操作图标通常 16px，导航可用 18px；同组统一线宽，建议沿用库的默认 2px。

装饰图标从辅助技术中隐藏；功能图标置于真实按钮内，提供具体可访问名称。错误和警告始终伴随文字，不能仅靠图标颜色区分。

## 17. 响应式与无障碍

### 17.1 响应式策略

| 区间 | 布局策略 |
| --- | --- |
| 小于 640px | 沿用顶部移动导航；工具栏换行；模态底部弹层；抽屉全屏；表单单列 |
| 640–1023px | 沿用顶部导航；弹窗受视口限幅；工作区按容器宽度决定单/双列 |
| 1024–1279px | 左侧导航显示；桌面列表；抽屉沿用常规宽度 |
| 1280px 及以上 | 抽屉沿用 xl 宽度；剧集工作区有足够容器宽度时启用双列 |

320px 宽度下不得出现整页横向滚动。长路径、复杂二维映射表等确需保留结构的内容可在专属区域横向滚动；电影列表、表单和主要提交操作必须重排。宽屏 400% 缩放时按等效窄视口检查，不仅测试真实手机。依据：[W3C Reflow 说明](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)。

### 17.2 键盘与辅助技术

- 所有可操作内容使用语义按钮、链接、输入或对应的现有可访问组件。
- Tab 顺序与阅读顺序一致；不通过正数 tabindex 修复视觉布局。
- 键盘焦点始终可见，不能被固定页脚、裁剪容器或弹层遮挡。
- 弹窗遵循现有焦点约束；Escape 关闭遵循当前业务允许条件，阻塞操作不伪造可取消行为。
- 导航、视图切换与选择项提供正确的 current/selected/pressed 语义，视觉选中与语义同步。
- 表单标签与字段关联，错误说明可被读取；变化结果适度播报，不逐条播报每次转圈或进度帧。
- 颜色之外使用文字、位置或形状传达状态。
- 不禁用页面缩放；不以固定高度裁掉放大后的中文或英文标签。

## 18. 设计样例与内容约束

制作后续静态稿或页面预览时使用一组固定的虚构/示例状态，标明示例数据，便于跨主题和尺寸比较；不把演示记录写入真实媒体库。

| 样例 | 必须覆盖的视觉问题 |
| --- | --- |
| 短标题影片 + 正常海报 | 基础层级、角标、主要操作 |
| 超长中文/英文影片名 | 两行标题、详情可读、工具栏不挤压 |
| 无海报、无年份影片 | 中性占位，缺失字段不显示伪数据 |
| 中英双语 SRT + 单语 ASS | 语言、格式与实际可用操作的差异 |
| 超长字幕文件名及多层目录 | 列表省略与详情完整查看 |
| 未知语言、只读内嵌字幕 | 中性状态与操作能力边界 |
| 同一季正常集、缺字幕集、缺集 | 三种状态清楚区分 |
| 季包未匹配、冲突、部分失败 | 映射与结果的比较效率 |
| SubHD 限流、Jellyfin 不可用 | 局部错误与条件入口 |
| 中文与英文设置页 | 字段扩展、错误换行、保存反馈 |

文案采用具体动词和对象，例如“上传字幕”“偏移时间”“已提交搜索”；避免“智能处理”“一键优化”等无法说明实际行为的名称。样式设计不能改变语言检测、规范化规则或来源含义。

## 19. 后续实现映射与建议顺序

本节记录实施范围。第 1–5 阶段已落地；第 6 阶段的主题/语言/触屏/键盘验收仍按清单回归。

| 阶段 | 范围与主要位置 | 完成标志 |
| --- | --- | --- |
| 1. 基础令牌 | `frontend/src/app/globals.css`、`frontend/tailwind.config.ts`、字体配置 | 四种主题模式、颜色职责、圆角和文字尺度一致 |
| 2. 共享基础组件 | `frontend/src/components/ui/`、`control-sizes.ts` | 按钮、字段、标签、弹层及状态矩阵一致 |
| 3. 应用外壳与媒体库 | `app-shell/`、`shared/library-*`、`movie-list-panel`、`tv-series-list-panel` | 搜索/排序/视图/分页不变，海报与列表符合新风格 |
| 4. 字幕与剧集工作区 | `movie-subtitle-drawer`、`subtitle-track-card`、`tv/` | 长内容可读，操作层级、批量映射和抽屉一致 |
| 5. 设置与操作弹窗 | `dashboard/`、`shared/settings/`、`subtitle/dialogs/`、日志和登录 | 表单反馈、预览、集成状态和危险操作一致 |
| 6. 全流程验收 | 主题、语言、触屏、键盘、缩放、真实状态 | 完成下节验收并同步现行文档 |

上表中第 3–5 阶段的组件简称均位于 `frontend/src/components/subtitle-manager/`，登录组件位于 `frontend/src/components/auth/`。

实施注意事项：

- 先升级共享令牌与组件，再处理页面，防止不同页面各有一套半成品样式。
- 主题、语言、视图及导航折叠偏好的持久化语义保持稳定。
- 保留静态导出能力，不引入依赖 Next 服务端运行的样式或图像能力。
- 海报继续使用现有图像来源和占位方式，不引入额外付费图片或在线字体依赖。
- 格式转换、备份、删除、SubHD 和 Jellyfin 的行为边界来自现有业务，样式改造不改变它们。
- 如果实施涉及语言识别或标准化规则，应单独处理共享语言契约；不将其混在样式修改中。
- 基础尺寸变更同步 `frontend-ui.md`；弹窗结构或尺寸变更同步 `frontend-dialogs.md`。本指南在实施时更新状态，明确哪些已落地。
- 纯文档交付只检查文档与变更范围。实际前端改造阶段再运行适用的 `bun test`、`bun run lint`、类型检查和 `bun run build`；容器交付前静态构建必须通过。

## 20. 验收清单

### 20.1 视觉一致性

- [ ] 主色只承担主要操作、选择和焦点等明确职责，没有全页蓝紫装饰。
- [ ] Light、Dark、OLED 都能区分画布、内容和浮层；System 正确跟随系统。
- [ ] 按钮、标题、导航使用自然无衬线排版；等宽字体仅用于合适的技术信息。
- [ ] 主要文字不低于规定字号，辅助文字在实际表面上满足可读性要求。
- [ ] 面板、控件、海报和弹窗使用统一圆角及间距尺度。
- [ ] 海报无缩放跳动；无海报状态保持相同结构与尺寸。
- [ ] 没有通过低对比度占位文字、细小角标或过多阴影制造层级。

### 20.2 交互与信息准确性

- [ ] 选中、悬停、焦点、错误和加载可区分，并正确表达组合状态。
- [ ] 搜索、排序、视图切换、分页和返回详情后的上下文没有退化。
- [ ] 文件名、影片、季、集和最终确认对象可明确辨认。
- [ ] 外挂与内嵌字幕、缺集与缺字幕、提交成功与执行完成没有混淆。
- [ ] 删除、替换和批量操作保留现有保护与关键说明。
- [ ] 集成关闭、网络失败、空结果及真实零数量有不同表达。
- [ ] 部分失败保留逐项结果；没有虚构进度、评分或成功状态。

### 20.3 尺寸、主题和可访问性

- [ ] 检查 320、390、768、1024、1440、1920px 等代表宽度，并包括短高度视口。
- [ ] 四种主题模式均有基础检查；三种实际配色均检查关键状态。
- [ ] 中英文均覆盖媒体库、长文件名、设置、批量映射和错误文案。
- [ ] 手机软键盘与底部安全区不会遮挡字段错误或提交入口。
- [ ] 大尺寸触屏仍有足够点击区域，不误用桌面 32px 行操作目标。
- [ ] 纯键盘可完成打开详情、操作菜单、表单提交与关闭返回。
- [ ] 普通内容在等效 320px 宽度可重排；必要二维表仅局部滚动。
- [ ] 实际 hover、selected、invalid、disabled 与 loading 颜色经过组合检查。
- [ ] 减少动效偏好有效；没有整页持续闪烁或无意义脉冲。

### 20.4 设计交付完成条件

后续实施稿至少包含：媒体库海报与列表、电影字幕抽屉、剧集单集与批量面板、设置页、一个简单表单、一个危险确认、字幕预览，以及加载/空/失败状态。通过这些页面验证同一套风格能覆盖真实操作，再将其视为完整的设计落地。
